# 웹 이용 집계

웹 집계 코드는 2026-09-24에 배포했고 같은 날 Firebase 규칙을 게시했다. 실제 웹 방문 기록 1건이 `seedWebTelemetry/v1/days/20260924/visitors`에 생기는 것을 확인했다. 규칙 게시 전 방문은 집계되지 않는다. Android Play Console 수치와 섞지 않는다.

- `방문 브라우저`: 서울 날짜별로 브라우저의 별도 익명 Firebase UID를 한 번만 기록한다. 사람 수나 계정 수의 정확한 대체값은 아니다. 브라우저 데이터를 지우거나 다른 기기를 쓰면 새 방문자로 잡힌다.
- `전투 진입`: 새 판 시작과 체크포인트 이어하기 횟수를 기록한다. 개발자 실험과 로컬 서버는 제외한다.
- `로그인 실패`: Google·Apple·게스트 로그인 실패를 네 종류(network/config/popup/other)로만 센다. 사용자가 계정 선택을 취소한 경우 제외한다.

저장 위치는 Firebase Realtime Database의 `seedWebTelemetry/v1/days/YYYYMMDD`다. 게임 계정과 별도의 익명 인증을 쓰며 이름·이메일·점수·조합·상세 오류 문구를 보내지 않는다. 집계 통신이 실패해도 게임과 계정 기능에는 영향을 주지 않는다. Android 앱과 localhost에서는 초기화하지 않는다.

## 적용 및 확인 기록

1. Firebase Console의 `jpmathlab-default-rtdb` 실제 규칙을 읽어 저장소 파일의 기존 9개 최상위 규칙과 모두 일치함을 확인했다. `seedWebTelemetry`를 제외한 동일 규칙을 `.work/firebase-rules-before-web-telemetry-20260924.json`에 백업했다.
2. 기존 규칙 9개가 모두 그대로인지 게시 전 다시 검사한 뒤 집계 블록만 추가했다. 클라이언트 읽기는 막고 인증된 익명 UID가 자기 경로에 `true`만 쓰도록 제한한다.
3. 실제 공개 웹을 새 탭에서 열어 2026-09-24 방문 기록이 생성된 것을 Firebase 데이터 탭에서 확인했다. 전투 시작은 명예의 전당 이용규칙 동의가 필요한 실제 흐름을 건드리지 않기 위해 여기서는 생성하지 않았다. 로컬 `?inspect=1`은 집계하지 않는다.
4. 이후 수치는 Firebase Console의 `seedWebTelemetry/v1/days`에서 확인한다. 관리 서비스 계정이 설정된 컴퓨터라면 `node tools/web-telemetry-report.mjs --days=14`로 이름 없는 집계표를 출력할 수 있다.

게시 이전 웹 방문은 복구할 수 없다. 첫날 수치에는 개발 과정의 확인용 방문 브라우저 1개가 포함된다.

## 2026-09-25 개발자 이용 현황 확장

개발자 실험실의 `이용 현황`은 서울 날짜 기준 오늘과 최근 7일을 보여준다. 웹/Android 앱 설치별 방문, 판 시작, 화면이 보이는 동안 실제 전투 시간, 완주와 사망을 집계한다. 개발자 실험 플레이는 제외한다. 게임 계정과 분리된 익명 UID만 보내며 점수·도감·조합·이름·이메일은 보내지 않는다. 한 사람이 기기 두 대를 쓰면 두 방문 기기로 보일 수 있다.

2026-09-25에 Firebase Console에서 관리자 전용 읽기 및 웹·Android 집계 쓰기 규칙을 게시하고, 다시 열어 저장소의 집계 규칙과 일치함을 확인했다. Google Play 데이터 보안 양식의 앱 상호작용·기타 작업 수집을 필수 및 애널리틱스 용도로 갱신해 저장했다. 앱 설치별 수치·전투 시간·결과는 새 버전이 배포된 뒤부터만 쌓이며 과거 기록으로 복원할 수 없다.
